# Walkthrough — v1.16 #3: Router override real (last-wins)

Fecha y hora: 2026-07-09 17:32 | Agente: core-dev | Modelo: claude-opus-4-8

## Contexto
Hallazgo **1.2 (P0)**: `Core\Router::dispatch()` hacía **first-match-wins** (`return` en el
primer match), pero la doc decía "la app pisa al core". Una ruta de la app con el mismo path
que el core (p. ej. `/`) **nunca se alcanzaba** → nsCheckout tuvo que resolver la home con un
`rewrite` en nginx. Además, el bloque de rutas de app se cargaba **a mitad** de `routes.php`,
con rutas del core (backups) **después**.

## Qué se hizo
1. **`Core\Router::add()` — override last-wins:** índice `method+path → posición`; registrar
   una ruta ya existente **reemplaza** la anterior en su lugar (no duplica). `dispatch()` sigue
   igual (first-match), pero ahora solo hay una entrada por `method+path`, así que gana la
   última registrada. Métodos distintos del mismo path (GET vs POST) no se confunden. Rutas con
   parámetro (`/u/{id}`) se pisan por patrón.
2. **`config/routes.php`:** el bloque de rutas de la app se movió **al final**, después de
   TODAS las del core (incluidos backups). Comentario corregido: ahora describe el override
   real.

## Verificación
- Suite: **282 PASS / 0 FAIL / 1 SKIP** (4 tests nuevos en `tests/unit/RouterOverrideTest.php`):
  app gana al core en `/`; GET/POST no se cruzan; override por patrón con parámetro; rutas
  distintas conservan orden.
- `core-lock.json` regenerado, sin drift.

## Archivos tocados

## Cómo lo usa un proyecto derivado
En `config/routes.app.php`: `$router->get('/', 'Front\CheckoutController@index');` → pisa la
home del core sin tocar el core ni nginx.
