## #1 — Cliente HTTP con transporte inyectable + retries (hallazgo 1.10)
- Enhance de `App\Services\Http` (ya existía con postJson/postRaw/postStream): se agregó
  **transporte inyectable** (`setTransport`/`resetTransport`) que estandariza el "poster
  inyectable" que los connectors duplicaban, más **`get()`**, **`request()`** genérico con
  **retries** (reintenta status 0 y 5xx, backoff lineal, no reintenta 4xx) y decodificación JSON.
- `postJson`/`postRaw` ahora rutean por el transporte (mockeables) **manteniendo el retorno
  idéntico**; `postStream` intacto. Retrocompat verificada: el test real de host muerto
  (`postJson` a 127.0.0.1:2 → ok=false) sigue verde. 7 tests (`HttpClientTest`).

## #2 — SignatureVerifier de webhooks entrantes (hallazgo 1.10)
- Nuevo `Core\Webhooks\SignatureVerifier`: `verify()` (firma simple `sha256=<hex>`, acepta hex
  crudo, **round-trip con `Webhook::sign`** del core), `verifyTimestamped()` (estilo Stripe/MP:
  `t=..,v1=..`, HMAC sobre template `{ts}.{payload}`, **anti-replay** por tolerancia, claves de
  header configurables). Comparación **constant-time** (`hash_equals`). 6 tests.
